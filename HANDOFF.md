## 2. Профиль технологии v2/v3 (в `main`)

### Зачем
Версия 1 (`R/05_tech_profile.R`, на сайте): 3–5 утверждений на Engine записаны вручную, темы OpenAlex дал
классификатор `/text/topics`, коды CPC подобраны вручную. Задача — формальная, воспроизводимая процедура:
оценить **все** темы OpenAlex и **все** группы CPC для каждого Engine, а потом вручную выбрать топ-5.
v1 остаётся на сайте без изменений. **v1 — не эталон**: это прежний ручной выбор, обосновать его сейчас нельзя.
Мы просто помним, что он есть, и показываем его для справки.

На сайте: схема v2/v3 стоит в начале страницы `methodology.html` (раздел «Technology profile: versions 2 and 3»,
пометка *In progress*); ниже — раздел «Technology profile, version 1» с таблицами профиля v1. Ссылка
«Профиль технологии» на схеме Pipeline ведёт на раздел v1 (`#technology-profile`).

### Процедура (схема: `tech_profile_v2_procedure.svg`, упрощённая, v2 и v3 отдельными дорожками; пользователь дорабатывает её вручную)
- **Справочники:** 4 516 тем OpenAlex (название + описание + ключевые слова, API `/topics`, кэш
  `data/raw/openalex_topics.json`) и 9 867 основных групп CPC (название подкласса + группы, локальный
  `CPCTitleList202608`).
- **Модели:** SPECTER2 (`allenai/specter2_base`, адаптеры `specter2` для тем и `specter2_adhoc_query` для текстов
  гранта) → темы OpenAlex; PatentSBERTa (`AI-Growth-Lab/PatentSBERTa`) → CPC. Две отдельные дорожки:
  тексты грантов эмбеддятся обеими моделями.
- **Вход v2:** название + каждое предложение аннотации (203 текста; финальная фраза NSF «This award reflects…» убрана).
- **Вход v3:** только научно-технические фрагменты, извлечённые фиксированным промптом
  `py/prompts/v3_extract_technical.md`. Извлечение сделано в чате (Claude Opus 5.5, один прогон):
  `data/manual/tech_v3_fragments_raw.csv`, 123 фрагмента. Каждый фрагмент обязан быть дословной подстрокой
  своего предложения — скрипт проверяет и выбрасывает остальные (сейчас 123/123 прошли).
- **Маскировка имени Engine:** акронимы (BRIDGES, FAST, IMPACT, NEO-SMART, RETI, STELLAR, RuralSTAMINA, QuantumCT,
  NSPIRE, CMC, ACMA) заменяются на «the Engine», иначе BRIDGES → мосты (E01D), IMPACT → снаряды (F42B).
  «Seafood» не маскируется: это обычное слово о технологии. Правило в `engine_name_tokens()`.
- **Центрирование:** из эмбеддингов каждого набора вычитается его средний вектор, затем нормировка.
  Без этого косинусы SPECTER2 лежат в узком коридоре 0.61–0.75 (идея пользователя; заметно улучшило темы).
- **Четыре оценки** на пару Engine × пункт (все сохраняются): `max` (максимум по предложениям/фрагментам),
  `centroid` (к среднему вектору Engine), `max_bg`, `centroid_bg` (минус среднее по остальным 11 Engines).
  Используются: темы — `max_bg`, CPC — `centroid` (константа `METHOD` в скрипте; рабочий выбор, а не вывод из совпадения с v1).
- **Шаг LLM** (оценка топ-50 с обоснованием и цитатой) — спроектирован, **не запускался**: нет ключа Anthropic API.

## 3. План: v3.1 (решено 2026-11-14)

### Решения
- Это **доработка v3, а не v4**: профиля v3 ещё нет (есть только рейтинги, отбор не делался), суть та же —
  только научно-технические фрагменты гранта, оценка всех тем и кодов. v4 — если поменяется сама идея профиля
  (выбор по охвату данных, вход не только из гранта).
- **v2 остаётся для сравнения** и прогоняется с теми же исправлениями и тем же отбором: v2 и v3.1 должны
  отличаться только входом.
- **Профиль по гранту, данные — только проверка.** Выбирать коды по охвату патентов региона нельзя: тогда
  Patent LQ региона высок по построению (круговое рассуждение). Охват патентов США в целом можно использовать,
  чтобы выбрать между одинаково близкими кандидатами.
- **Ядро и широкий профиль.** Ядро — 2–3 темы и 2–3 кода CPC на каждую технологию гранта, проверенные глазами.
  Широкий профиль — всё выше порога релевантности. Метрики считаются в обоих вариантах; совпадение выводов =
  устойчивость.
- **Патенты без лимита по числу кодов** (все данные USPTO локально), но с одним правилом порога для всех 12 Engines.
- **Темы OpenAlex тоже можно брать шире:** статьи команды скачиваются целиком и фильтруются локально; для
  статей партнёров OpenAlex берёт плату за страницу из 200 работ, а не за тему (темы объединяются через «|»,
  до 100 в фильтре). Ограничение — смысл (узкие темы ловят чужие статьи), а не стоимость.

### Шаги
1. **Промпт v3.1** (`py/prompts/v3_1_extract_technical.md`, v3.0 не трогать): не извлекать отрасли-применения
   («automotive, packaging», «aerospace, defense») и общие качества («resilience, efficiency») без технического
   объекта; **для каждого фрагмента — метка технологии гранта** (3–5 на Engine), чтобы отбирать по технологиям.
   Проверка дословности как в v3. По возможности 3 независимых прогона (нужен ключ Anthropic API) для устойчивости.
   **Сделано 2026-11-14 вручную в чате Claude Code, один прогон, НЕ через API** (ключа Anthropic API в проекте нет).
   Прогон **невоспроизводим**: скрипта нет; у модели в чате кроме промпта был весь разговор (в том числе разбор
   v2/v3); проверки дословности и меток сделаны разовым скриптом вне репозитория. Пользователь решил, что это
   допустимо, с пометкой. Если появится ключ — скрипт с 3 прогонами через API и сравнение с этим прогоном.
   Результат: `data/manual/tech_v3_1_fragments_raw.csv` — 86 фрагментов
   (в v3 было 123), 2–5 технологий на Engine (всего 39), все фрагменты дословные (2 с неразрывным дефисом
   «‑» восстановлены по тексту), метки технологий только из слов фрагментов. Ушли отрасли, «resilience/reliability»
   и повторы общих фраз. Спорные решения: STELLAR — применения («medical diagnostics and vision care»,
   «high-speed communications») не извлечены как отрасли; BRIDGES — «digital twins and AI-enabled
   decision-support systems» отдельной технологией (применяются и к культурам, и к производству);
   IMPACT — 5 технологий (MSK как область, лекарства и биологики, диагностика, данные и AI, ортопедические устройства).
2. **Маскировка:** слово «Engine(s)» и акронимы удалять или заменять нейтральным «the program», а не «the Engine»
   (PatentSBERTa читает engine как двигатель → F01/F02). Для v2 тоже.
3. **Текст группы CPC = название подкласса + группы + названия подгрупп первого уровня** (даст «hydrogen»,
   «direct reduction», «flotation», «magnetometer»). Индексные группы 2000+ и «/99» исключить или понизить.
   Коды v1 обновить под CPC 2026 (H01L21 → H10P) — только для справки.

## 6. Общий первый шаг: технологии гранта (2026-11-17, облако)

Решено: v1 и v3.1 строятся от **одного списка технологий гранта**, а различаются только способом выбора тем и
кодов (v1 — модель называет по памяти; v3.1 — эмбеддинги по полным спискам + проверка). v2 остаётся на схеме как
тупик: эмбеддинги по всем предложениям без шага «технологии» → шум (регион, кадры, «Engine» → двигатели).

- **Прогоны:** три независимых подагента (видят только промпт и текст 12 грантов; не API, в чате — помечать).
  Вход `scratchpad`-копия `data/processed/tech_v2_sentences.csv`. Проверка: `py/05v3_2a_stability.py <tag>`.
- **Сравнили три промпта** (`py/prompts/`): `grant_technologies_v3_2.md` (подробный, серые зоны),
  `grant_technologies_minimal.md` (только идея задачи), `grant_technologies_minimal_plus.md` (минимальный
  + 2 фразы: «обычно 2–5 технологий, один журнал / патентный эксперт» и «не делать технологией широкую область»).

  | | v3.2 | minimal | **minimal_plus** |
  |---|---|---|---|
  | технологий в итоге (на Engine) | 37 (2–4) | 60 (2–10) | **43 (2–5)** |
  | Engines, где число технологий плавает | 7 | 9 (до 4) | **4 (≤1)** |
  | ARI прогонов | 0.77 | 0.78 | **0.85** |
  | общие области («advanced manufacturing»…) | 13 | 9 | **2** |
